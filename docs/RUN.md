# Запуск, настройка и разработка

## Требования

- Windows 10/11 или Linux, Python 3.11+
- Для реального STT: ~150 МБ на модель Whisper `base` и несколько ГБ RAM
- GPU не обязателен (`WHISPER_DEVICE=cpu`)

## Установка

```powershell
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
copy .env.example .env
python run.py
```

Либо одной командой: `.\run.ps1`.

Откройте http://127.0.0.1:8080.

Проще всего на Windows - `start.bat` в корне проекта: сам поднимет Docker-вариант или, если Docker нет, venv с SQLite, напечатает стартовые пароли и откроет браузер (подробно в README, раздел «Одной командой»).

Если порт занят предыдущим запуском:

```powershell
python run.py          # сообщит, что сервер уже работает
python run.py --replace
python run.py --stop
```

WinError 10048 — это занятый порт, не ошибка кода.

## Переменные `.env`

| Переменная | Смысл | По умолчанию |
|---|---|---|
| `APP_HOST` / `APP_PORT` | адрес | `127.0.0.1` / `8080`. Локальный запуск также открывает `localhost` |
| `APP_DEBUG` | OpenAPI `/docs` | `false` |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | первая учётка администратора, если её ещё нет | `admin` / пусто: пароль генерируется при первом запуске и пишется в `data/initial_credentials.txt` |
| `TRUSTED_PROXIES` | адреса reverse-proxy, от которых принимается `X-Forwarded-For` | пусто |
| `WHISPER_MODEL` | `tiny`, `base`, `small`, … | `base` |
| `WHISPER_DEVICE` | `cpu` или `cuda` | `cpu` |
| `WHISPER_COMPUTE_TYPE` | `float32`, `int8_float32` или `int8`; int8 быстрее, но проверьте WER (docs/PERFORMANCE.md) | `float32` |
| `MAX_PARALLEL_JOBS` | слоты очереди | `1` |
| `MAX_UPLOAD_MB` | размер файла | `80` |
| `MAX_DURATION_SEC` | лимит длины | `900` (15 мин) |
| `ALLOW_REMOTE` | слушать не только localhost | `false` |
| `PII_MASKING` | маска персональных данных в выдаче | `true` |
| `DISPLAY_TZ` | часовой пояс времени в журнале аудита | `Europe/Moscow` |
| `JWT_TTL_HOURS` | срок токена | `12` |
| `WHISPER_BEAM_SIZE` | луч декодера, 1–5 | `5` |
| `WHISPER_BATCH_SIZE` | пакет для записей от 90 с | `8` |
| `WHISPER_CPU_THREADS` | потоки CPU, `0` — само | `0` |

`APP_HOST`, отличный от `127.0.0.1` / `localhost`, без `ALLOW_REMOTE=true` не запускается. Для сети перед приложением нужен TLS-прокси. Подробности — в [SECURITY.md](SECURITY.md) и [PERFORMANCE.md](PERFORMANCE.md).

Ключи `data/master.key` и `data/jwt.secret` создаются при первом старте.

## Модель Whisper

Ищется в `data/models/faster-whisper-<WHISPER_MODEL>/model.bin` (например `faster-whisper-small`). Если файла нет, модель один раз скачивается с Hugging Face в эту папку (нужна сеть). После этого контур офлайн. Скорость и точность на своей машине: `python scripts/benchmark.py` (см. [PERFORMANCE.md](PERFORMANCE.md)).

## Типичные ситуации

**Сервер не открывается.** Проверьте, что процесс слушает 8080, и что в браузере именно `127.0.0.1`, не другой хост.

**«Запись слишком короткая».** Файл короче 0,4 с или без речи.

**«Не удалось декодировать».** Это не WAV/MP3/OGG или файл повреждён. Сигнатура должна совпадать с расширением.

**Пустая расшифровка.** Шум, музыка, слишком тихая запись. Демо-звонки в журнале показывают оценку без аудио.

**Повторный `run.py` падает.** Используйте текущий процесс на :8080 или `python run.py --replace`.

## Озвучка демо-звонков

По умолчанию выключена: программа при старте ничего не скачивает. Чтобы демо-звонки можно было прослушать:

1. `python -m pip install -r requirements-voice.txt` (CPU-сборка torch).
2. В `.env`: `DEMO_VOICE_ENABLED=true`.
3. Перезапустить. Модель Silero `v4_ru.pt` (~40 МБ) скачивается один раз в `data/models/silero-ru-v4.pt`.

Демо-звонки озвучиваются в стерео: оператор в левом канале, клиент в правом, пауза 0,6 с между репликами. Поэтому после «Переобработать» роли берутся из каналов. Проверено 17.11.2026 с torch 2.15.0+cpu: 14 демо-звонков озвучены за 13-14 с, после переобработки реплики и роли совпали с исходными.

Модель - это `torch.package`, то есть pickle. Поэтому файл проверяется по SHA-256 (`DEMO_VOICE_MODEL_SHA256`, значение по умолчанию снято с файла 17.11.2026) и при скачивании, и перед каждой загрузкой. Если хеш не совпал, файл не загружается, демо остаются без звука. Источник меняется через `DEMO_VOICE_MODEL_URL` (только https), хеш тогда нужно задать свой.

## Стерео-записи: роли по каналам

Если запись двухканальная (оператор и клиент на разных каналах, как пишут АТС контакт-центров), роли размечаются по громкости каналов: каждая фраза, а на записях до 3 минут каждое слово, относится к каналу, который в ней в 1,6 раза громче. Какой канал у оператора, определяется по фразам оператора («банк Центр-инвест», «меня зовут», «чем могу помочь») или задаётся явно.

- `STEREO_DIARIZATION=true` - включено по умолчанию.
- `STEREO_OPERATOR_CHANNEL=auto` - или `left` / `right`, если канал оператора известен.

Если каналы почти одинаковые (моно, сохранённое как стерео) или явный канал есть меньше чем у 60% фраз, работает прежняя разметка по паузам и речевым маркерам.

## Оценка локальной LLM (Ollama), необязательно

По умолчанию выключена, оценка идёт только по правилам `app/quality.py`. Чтобы добавить мнение локальной модели:

1. Установить [Ollama](https://ollama.com) и скачать модель, например `ollama pull qwen2.5:7b-instruct`.
2. В `.env`: `LLM_PROVIDER=ollama`, при желании `LLM_MODEL=...`, `OLLAMA_URL=http://127.0.0.1:11434`, `LLM_WEIGHT=0.5`, `LLM_TIMEOUT_SEC=120`.

Модель получает расшифровку с ролями, в которой персональные данные уже замаскированы, и отвечает JSON: четыре оценки 0-100, до 4 советов и краткий итог. Итоговые метрики = (1 - `LLM_WEIGHT`) × правила + `LLM_WEIGHT` × модель. Советы модели помечаются «ИИ:», в чек-листе появляется строка «Оценка локальной LLM». Если Ollama не запущена, не уложилась в таймаут или вернула кривой JSON, звонок оценивается только правилами, очередь не останавливается.

`OLLAMA_URL` по умолчанию принимается только локальный (`127.0.0.1`, `localhost`, `::1`), чтобы текст звонков не уходил с машины. Удалённый адрес работает только с `LLM_ALLOW_REMOTE=true`.

Оценки правил в промпт не передаются: модель оценивает звонок сама. Иначе небольшая модель просто копирует подсказку (на замере `qwen2.5:3b` так сделал в 4 звонках из 6). Длина ответа ограничена 600 токенами, чтобы зависшая генерация не держала очередь до таймаута.

Какую модель брать (замер 17.11.2026, CPU Xeon 8 vCPU, 15 ГБ RAM, без GPU, 14 демо-звонков, `python scripts/benchmark.py llm --model ... --calls 14 --warmup`):

- `qwen2.5:7b-instruct` (4,7 ГБ, около 5,2 ГБ RAM при работе) - рекомендуемая. Валидный JSON 14/14, 11,1-20,2 с на звонок, в среднем 14,7 с; первая загрузка модели 19 с. Плохие звонки оценивает жёстче и стабильнее, чем 3b.
- `qwen2.5:3b` (1,9 ГБ, около 2,5 ГБ RAM) - для ноутбука с 8 ГБ. Валидный JSON 14/14, 5,1-10,4 с, в среднем 7,4 с; загрузка 9-10 с.

С включённой LLM звонок длиной 16-38 с обрабатывается целиком (Whisper `base` + правила + `qwen2.5:7b-instruct`) за 16-29 с, из них LLM 14-26 с. Длинная расшифровка обрезается до 12 000 символов (начало и конец). 10-минутная запись с LLM обработана за 91,8 с, из них 80 с - модель.

Если Ollama остановлена, звонок оценивается только правилами (проверено: 2,6 с на звонок, в журнале `Ollama недоступна`). Если модели нет, в журнале будет подсказка `ollama pull <модель>`.

В docker compose Ollama поднимается отдельным сервисом: `LLM_PROVIDER=ollama` в `.env`, затем `docker compose --profile llm up -d --build` и `docker compose exec ollama ollama pull qwen2.5:7b-instruct`. Порт Ollama наружу не публикуется.

## PostgreSQL вместо SQLite (необязательно)

По умолчанию база - SQLite в `data/app.db`, ничего настраивать не нужно. Чтобы работать с PostgreSQL, задайте `DATABASE_URL`:

```
DATABASE_URL=postgresql+psycopg://rechkontrol:ПАРОЛЬ@127.0.0.1:5432/rechkontrol
```

- Драйвер `psycopg[binary]` уже в `requirements.txt`. Адрес вида `postgresql://...` тоже принимается и переводится на psycopg.
- Таблицы создаются при первом запуске, новые колонки добавляются так же, как в SQLite.
- Защита SQLite (запрет ATTACH и `writable_schema`, PRAGMA) действует только для SQLite. Для PostgreSQL доступ, пароль, TLS и резервные копии настраиваются на стороне сервера. В админке вместо пунктов про SQLite показываются версия сервера и состояние TLS.
- Если сервер базы не на `localhost` и в адресе нет `sslmode=require`, в журнале появится предупреждение: если база на другой машине, расшифровки идут по сети открытым текстом.
- Ключ шифрования аудио, JWT-секрет и сами аудиофайлы по-прежнему лежат в `data/`, их нужно сохранять вместе с базой.
- Переноса данных из SQLite в PostgreSQL нет: новая база начинается с демо-звонков и новых стартовых паролей.

Осторожно: если в окружении уже есть чужой `DATABASE_URL` (его часто задают для других проектов), программа подключится к нему. Задавайте `DATABASE_URL` в `.env` проекта или явно очищайте его.

### docker compose

`docker-compose.yml` поднимает PostgreSQL 17 и само приложение:

1. В `.env`: `POSTGRES_PASSWORD=...` (только буквы и цифры, например `openssl rand -hex 24`: пароль подставляется в URL).
2. `docker compose up -d --build`
3. Стартовые пароли кабинета: `docker compose logs app` или `docker compose exec app cat data/initial_credentials.txt`.

Оба порта публикуются только на `127.0.0.1` (5432 и 8080; порт приложения можно сменить через `APP_PORT` в `.env`). Данные PostgreSQL лежат в томе `pgdata`, ключи, аудио, модели Whisper и стартовые пароли приложения - в томе `appdata` (`/app/data` в контейнере). Bind-mount `./data` не используется: Docker создаёт такую папку от root, и приложение (uid 1000) не может в неё писать. Первый звонок после старта ждёт скачивания модели Whisper в этот том (около 150 МБ для `base`).

Проверено 17.11.2026 на Docker 29.10.0 и Compose v5.7.1: сборка, старт с PostgreSQL 17, стартовые пароли, обязательная смена пароля, загрузка и расшифровка WAV (клип 10 с и запись 10,2 мин), экспорт CSV/JSON, 403 для оператора, оценка через сервис `ollama`.

### Тесты против PostgreSQL

```
TEST_DATABASE_URL=postgresql+psycopg://user:pass@127.0.0.1:5432/rechkontrol_test pytest
```

Тесты не читают `DATABASE_URL` из окружения и чистят только базу, в имени которой есть `test`. Без `TEST_DATABASE_URL` они идут на временной SQLite.
