# Персональные данные (152-ФЗ)

Записи звонков и расшифровки содержат персональные данные клиентов и сотрудников: голос, ФИО, телефон, номера карт и договоров, иногда паспорт и СНИЛС. Ниже - что для этого делает РечьКонтроль и что остаётся на стороне банка. Это технический документ разработчиков, а не юридическое заключение.

## Что должен оформить банк (вне программы)

- **Цель и основание обработки.** Цель - контроль качества обслуживания и обучение операторов. Основание для клиентов обычно - согласие или договор, для сотрудников - трудовой договор и локальный акт. Формулировки определяет юрист банка (ст. 6, 9 152-ФЗ).
- **Уведомление о записи.** Клиент должен узнать о записи до начала разговора: «Разговор записывается для контроля качества». Обычно это фраза автоинформатора АТС. Программа может это проверять, см. ниже.
- **Голос как биометрия.** Программа не строит голосовые отпечатки для опознания человека: роли «оператор / клиент» определяются только внутри одного звонка и нигде не сохраняются. Поэтому записи не используются как биометрия в смысле ст. 11. Если банк захочет опознавать клиента по голосу, нужно отдельное основание и ЕБС.
- **Уведомление Роскомнадзора, перечень ИСПДн, модель угроз, уровень защищённости** (ПП РФ № 1119, приказ ФСТЭК № 21) - на стороне банка. Программа рассчитана на работу в его закрытом контуре.
- **Удаление по запросу субъекта.** Администратор удаляет звонок в кабинете (кнопка удаления в карточке звонка), удаляются аудио, расшифровка и оценка, действие пишется в журнал.

## Что делает программа

### Данные не покидают контур

Распознавание и оценка идут на этой машине. По умолчанию кабинет слушает только `127.0.0.1`. LLM только локальная (Ollama), нелокальный адрес запрещён (`LLM_ALLOW_REMOTE=false`). Подробнее в `SECURITY.md`.

### Шифрование при хранении

- **Аудио** - Fernet (AES-128-CBC + HMAC-SHA256), файлы `data/audio/*.bin`.
- **Расшифровки** - тем же ключом в базе: полный текст, реплики по ролям и цитаты-доказательства в оценке (`full_text`, `segments_json`, `checks_json`). В базе лежит строка `rkenc1:...`, без ключа текст не читается. Включено по умолчанию (`ENCRYPT_TRANSCRIPTS=true`).
- **Старые установки.** Открытые записи из прошлых версий читаются как раньше и шифруются сами при первом запуске новой версии. В SQLite старые страницы затираются (`secure_delete=ON`, checkpoint WAL).
- **Что не шифруется:** имя файла, дата, оператор, итоговые баллы, рекомендации, журнал аудита. Это нужно для фильтров и отчётов. Не кладите ФИО клиента в имя файла.
- Поиск по тексту звонков идёт после расшифровки в памяти, а не в SQL.

### Ключ отдельно от данных

Ключ ищется в таком порядке:

1. `MASTER_KEY` - сам ключ в переменной окружения (например, из секрета Docker или хранилища секретов банка).
2. `MASTER_KEY_FILE` - путь к файлу ключа.
3. `data/master.key` - старое место, только для совместимости. На странице «Безопасность» это отмечено как замечание.

Куда кладётся ключ по умолчанию:

- `start.ps1` без Docker сам прописывает в `.env` `MASTER_KEY_FILE=%LOCALAPPDATA%\RechKontrol\master.key`.
- В Docker ключ лежит в отдельном томе `appkeys` (`/app/keys/master.key`), данные - в томе `appdata`.

Перенос со старой версии автоматический: при первом запуске `data/master.key` копируется в новое место, копия сверяется, после этого старый файл удаляется и рядом остаётся метка `data/master.key.moved` (без ключа). Если потом путь к ключу потеряется, программа не создаст новый ключ молча, а остановится с понятной ошибкой: иначе все старые записи стали бы нечитаемыми. Если в старом и новом месте лежат разные ключи, программа тоже остановится и ничего не тронет.

Важно для бэкапов: копия `data/` или базы без ключа бесполезна, а ключ без данных ничего не раскрывает. Храните резервную копию ключа отдельно от резервной копии данных. Потеря ключа = потеря всех записей и расшифровок.

### Срок хранения и автоудаление

- `RETENTION_DAYS=365` по умолчанию: через 365 дней после загрузки звонок удаляется целиком - аудиофайл, расшифровка и оценка. `0` - не удалять автоматически.
- Проверка идёт при старте и затем каждые `RETENTION_CHECK_HOURS` часов (по умолчанию 6). Звонок, который прямо сейчас обрабатывается, не трогается.
- В журнал пишется `retention.purge` (в журнале - «удаление по сроку хранения») с числом и номерами удалённых звонков, без имён файлов и текста.
- Срок выбирает банк. 365 дней - разумная отправная точка для контроля качества и разбора жалоб. Если запись нужна дольше (спор, проверка), её надо выгрузить по регламенту банка до истечения срока.

### Журнал доступа

В журнал аудита пишутся: вход и выход, загрузка, **доступ к аудиозаписи** (`call.audio`, номер звонка; запись загружается в плеер при открытии карточки звонка, так что это и прослушивание, и скачивание), просмотр расшифровки без маски (`call.unmask`), экспорт CSV, Excel, JSON, PDF-отчёты, удаление, автоудаление по сроку, изменения чек-листа и пользователей. Время в базе в UTC, в кабинете показывается по Москве. Журнал видит только администратор.

### Минимизация и маскирование

- Аналитик и оператор видят расшифровку с маской: `[ФИО]`, `[ТЕЛЕФОН]`, `[КАРТА]`, `[СЧЁТ]`, `[ПАСПОРТ]`, `[СНИЛС]`, `[ИНН]`, `[EMAIL]`, `[ДАТА]`, `[НОМЕР]`. В экспорте то же самое.
- Без маски текст видит только администратор по явному запросу, и это пишется в журнал.
- Оператор видит только свои звонки.
- В резюме звонка имя оператора не пишется.

### Ограничения маскирования (честно)

Маска сделана на регулярных выражениях и словаре имён, это не NER-модель:

- Числа словами («четыре два семь шесть…»), продиктованные по одной цифре с паузами или с ошибками распознавания, могут не замаскироваться.
- Редкие имена, фамилии без имени и отчества, прозвища, адреса и названия организаций клиента могут остаться в тексте.
- Полнота маски на реальных звонках банка не измерялась. Перед пилотом нужно взять 50-100 обезличенных расшифровок и посчитать, сколько ПДн пропущено.
- Аудио не маскируется: голос и всё сказанное в записи остаются. Поэтому доступ к прослушиванию журналируется.

### Уведомление о записи в чек-листе

В чек-листе есть критерий «Уведомление о записи разговора» (по умолчанию выключен). Если включить его в редакторе чек-листа, звонок без фраз «разговор записывается», «ведётся запись», «в целях контроля качества» получит нарушение. Фраза ищется во всём разговоре, включая автоинформатор в начале записи. Если автоинформатор АТС в запись не попадает, критерий лучше не включать.

## Чего нет (на стороне банка или следующих версий)

- Вход через AD/LDAP/SSO и второй фактор.
- Шифрование ключа в HSM или в хранилище секретов (сейчас ключ - файл или переменная окружения).
- Отдельный журнал в SIEM: журнал аудита хранится в той же базе.
- Удаление по запросу субъекта по его данным (поиск всех звонков человека). Сейчас удаляется каждый звонок отдельно.
