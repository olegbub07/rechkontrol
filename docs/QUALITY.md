# Оценка качества диалога

Движок `app/quality.py` работает только по тексту и таймкодам. Облачные LLM не используются: записи не должны покидать контур.

## Четыре метрики (0–100)

Итог:

`0.28 × вежливость + 0.22 × полнота + 0.25 × скрипт + 0.25 × решение`

Грубая формулировка в речи оператора дополнительно снижает итог.

### Вежливость

- приветствие;
- обращение на «вы»;
- формулы вежливости;
- эмпатия, если клиент встревожен;
- отсутствие грубости и перебиваний.

### Полнота

- ответы на вопросы клиента;
- содержательность реплик оператора;
- пауза перед ответом (ориентир до 3 секунд).

### Скрипт

- представление;
- название компании (список настраивается);
- предложение помощи;
- уточнение запроса;
- корректное завершение;
- дополнительные обязательные фразы из настроек.

### Решение проблемы

- озвучено действие или результат;
- назван следующий шаг, срок или номер обращения;
- есть подтверждение, что вопрос закрыт;
- диалог не брошен и клиент не отправлен «не туда».

## Настраиваемый чек-лист

Администратор меняет чек-лист во вкладке «Скрипт» (блок «Чек-лист качества»): включает и выключает критерии, меняет названия, веса внутри метрики, ключевые фразы и вес каждой метрики в итоговой оценке. Аналитик видит чек-лист без права правки, оператор не видит.

- Хранится в БД (таблица настроек, ключ `checklist`), по умолчанию совпадает со встроенными правилами. Кнопка «Вернуть по умолчанию» сбрасывает его.
- Проверки на сервере, сообщения по-русски: пустое поле, буквы и `null` - ошибка (а не 0); вес критерия от 0 до 5 с шагом 0,1 (2,55 - ошибка), у включённого больше 0 (чтобы выключить пункт, снимается «Вкл.»); доля метрики больше 0 и не больше 1, до трёх знаков после запятой; у каждой метрики хотя бы один включённый критерий; у включённого фразового критерия хотя бы одна фраза (2–80 символов, до 80 штук). Запятая в дробях допускается.
- Доли метрик приводятся к сумме 1 при сохранении (1, 1, 1, 1 станет по 0,25), ответ `PUT` сообщает об этом в `message` и `normalized: true`. Форма считает сумму на лету.
- Браузерные проверки отключены (`novalidate`), форма сама подсвечивает неверное поле и пишет, что не так; сервер проверяет то же самое.
- Каждое изменение пишется в журнал аудита (`checklist.update`, `checklist.reset`) с перечнем изменённых полей. Сохранение без изменений возвращает `changed: false` и в журнал не пишется.
- Новые звонки оцениваются по сохранённому чек-листу. Готовые звонки можно пересчитать кнопкой «Пересчитать оценки звонков» (`checklist.rescore`): пересчёт идёт по сохранённой расшифровке, без Whisper и без LLM, поэтому вклад LLM при пересчёте не сохраняется. Заодно старые расшифровки чистятся от галлюцинаций Whisper (см. ниже).
- Известное ограничение: при `LLM_PROVIDER=ollama` смешивание с оценкой модели идёт с фиксированными долями, доли метрик из чек-листа на него не влияют.
- Названия компании и дополнительные фразы скрипта по-прежнему задаются в блоке «Скрипт».

API: `GET /api/checklist`, `PUT /api/checklist`, `POST /api/checklist/reset`, `POST /api/checklist/rescore`.

## Подсветка в расшифровке

В карточке звонка фрагменты реплик, на которые сработали правила, подсвечены цветом; при наведении видно правило и влияние на итоговую оценку в баллах.

- зелёный - фраза засчитала пункт чек-листа (приветствие, представление, вежливость, итог и т.д.);
- красный - нарушение: грубость, отправка «не туда», обращение на «ты» (у грубости ещё множитель итога);
- жёлтый - негативная лексика, влияет только на тональность;
- серый - персональные данные, скрытые маскированием (без маскирования - то, что будет скрыто);
- пунктирная метка над первой или последней репликой оператора - пропущенный пункт (нет приветствия, представления, названия компании, завершения).

Подсветка считается при открытии карточки по показанному тексту, так что маскированный и исходный текст подсвечиваются каждый по-своему. Пройден пункт или нет - берётся из сохранённой оценки звонка, фразы - из текущего чек-листа. Подсветку можно выключить переключателем над расшифровкой; при поиске по репликам показывается только совпадение с запросом. В API это поля `spans` и `markers` у каждой реплики `GET /api/calls/{id}` (смещения в символах UTF-16).

## Процент нарушений

Доля пунктов чек-листа, которые не пройдены. Именно это поле уходит в CSV/JSON как «процент нарушений».

## Тональность

Лексическая оценка речи оператора и клиента: `positive` / `neutral` / `negative`. Грубость фиксирует негатив.

## Рекомендации

Формируются только по проваленным проверкам, с конкретным советом («представьтесь по имени», «назовите номер обращения»). Если итог ≥ 88, звонок помечается как эталон для обучения.

## Роли в расшифровке

Whisper отдаёт слова с таймкодами. Реплики собираются по паузам в аудио, затем классифицируются маркерами КЦ («меня зовут», «чем могу помочь», «хочу открыть» и т.д.). Соседние куски одной роли сливаются.

Это эвристика для двух спикеров, без облачной диаризации.

## Правка ASR

`app/asr_clean.py` убирает галлюцинации Whisper: сегменты, где модель сама не уверена в речи (`no_speech_prob` > 0,6 при `avg_logprob` < -1, или `compression_ratio` > 2,8), одно слово подряд 4 раза и больше или кусок из 2-4 слов 3 раза и больше (оставляется одно повторение, «да да да» не трогается), «слова» из одной буквы («СППППП», «ммммм») и титры из обучающих видео («Субтитры сделал…», «Редактор субтитров…», «Продолжение следует», «Спасибо за просмотр»). Фильтр работает на новых звонках и при пересчёте старых.

`app/asr_fix.py` поправляет устойчивые ошибки модели `base` на банковской лексике: «Центр-инвест», «ИНН», «ЕГРИП», «счёт».

На записи длиннее 90 секунд текстовая подсказка в Whisper не передаётся: иначе название банка может появиться в тексте само, и проверка скрипта станет ложноположительной. Короткие клипы подсказку получают.

## Локальная LLM (необязательно)

При `LLM_PROVIDER=ollama` к оценке правил добавляется мнение локальной модели (`app/llm.py`): четыре метрики смешиваются с весом `LLM_WEIGHT`, советы модели идут первыми с пометкой «ИИ:». Модель видит только замаскированный текст. Без Ollama или при ошибке используется только оценка правил. Настройка: [RUN.md](RUN.md#оценка-локальной-llm-ollama-необязательно).
